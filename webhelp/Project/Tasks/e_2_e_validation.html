Validate End-to-End Connected Features

Run end-to-end validation scenarios to confirm that connected vehicle features such as emergency calls, infotainment, and remote commands work reliably across device, cloud, and application layers.

Before running end-to-end validation:

  • Device must be onboarded and in Active status.
  • Connectivity testing must have passed for the target device.
  • You must have Test Engineer or Admin role permissions.
  • All target application endpoints must be reachable and healthy.

End-to-end validation tests the complete journey of a feature — from a trigger event at the vehicle level, through cloud processing, to the final outcome in the user application. This is the final validation gate before a device or software release is cleared for production.

  1. Navigate to Test Center > E2E Validation.
  2. Select the device and the validation scenario to execute.
    OptionDescription
    Emergency Call (eCall) Simulates an emergency trigger and validates call routing and response time.
    Infotainment Streaming Validates media streaming quality, buffering, and handoff behavior.
    Remote Command Round-trip Issues a test command and verifies delivery, execution, and acknowledgment.
    OTA Update Delivery Pushes a test firmware package and verifies successful installation and rollback.
  3. Click Run Scenario to trigger the selected test.
  4. Monitor system response across all three layers in the E2E Monitor panel.
    1. Observe the Device Layer panel for trigger event confirmation.
    2. Observe the Cloud Layer panel for processing and routing status.
    3. Observe the Application Layer panel for delivery confirmation.
  5. Review the success criteria checklist at the end of the scenario run.
    Each scenario has predefined pass criteria. Examples:
    • eCall: Response routed within 2 seconds.
    • Remote command: Round-trip acknowledgment within 3 seconds.
    • OTA: Package installed with no integrity errors.
  6. Inspect the structured logs for each layer in the Log Viewer tab.
    Logs include timestamps, event IDs, and layer-specific diagnostic details.
  7. Export the validation report for sign-off and traceability documentation.

All connected features are confirmed to work reliably across the device, cloud, and application layers. The validation report is stored in the platform and linked to the device's compliance record.

If all E2E validation scenarios pass, the device is cleared for production deployment. If any scenario fails, review the layer-specific logs and re-run after remediation.
